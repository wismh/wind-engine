# MVVM & Data Binding

Wind uses the Model-View-ViewModel (MVVM) pattern for UI. Game logic does not directly manipulate UI nodes; instead, UI documents bind to fields and commands declared on a `ViewModel`.

---

## 1. Defining a `ViewModel`

Create a class inheriting from `engine::ui::ViewModel`:

```cpp
#include <engine/ui/view_model.h>
#include <engine/ui/bindable.h>
#include <engine/ui/command.h>

namespace game {

class HudViewModel : public engine::ui::ViewModel {
public:
    HudViewModel() {
        // Register properties and commands with their BindingIds
        property(engine::ui::intern("healthText"), healthText);
        property(engine::ui::intern("score"), score);
        command(engine::ui::intern("togglePause"), togglePause);
    }

    // Properties bound from XML MUST be camelCase
    engine::ui::Bindable<std::string> healthText{"100 HP"};
    engine::ui::Bindable<float> score{0.0f};

    // Commands bound to buttons
    engine::ui::RelayCommand togglePause;
};

} // namespace game
```

> [!IMPORTANT]
> **Naming Rule:** View-model fields bound from XML markup **must** be `camelCase` (e.g. `healthText`, `togglePause`). All standard C++ functions and members remain `snake_case`.

---

## 2. Generated Binders (`asset_ids.h`)

When you run `asset_codegen` on your UI document (e.g. `assets/ui/hud.xml`), it generates a type-safe binder struct in `<build>/generated/<game>/asset_ids.h`:

```cpp
// Auto-generated by asset_codegen
namespace assets::ui::hud_bind {
    static constexpr engine::ui::BindingId healthText = ...;
    static constexpr engine::ui::BindingId score = ...;
    static constexpr engine::ui::BindingId togglePause = ...;

    template<typename T>
    void bind(T& vm) {
        vm.property(healthText, vm.healthText);
        vm.property(score, vm.score);
        vm.command(togglePause, vm.togglePause);
    }
}
```

You can call the generated `bind()` method in your ViewModel constructor:

```cpp
#include <asset_ids.h>

class HudViewModel : public engine::ui::ViewModel {
public:
    HudViewModel() {
        assets::ui::hud_bind::bind(*this);
    }

    engine::ui::Bindable<std::string> healthText{"100"};
    engine::ui::Bindable<float> score{0.0f};
    engine::ui::RelayCommand togglePause;
};
```

---

## 3. Updating Data from Game Systems

In your game systems or frame updates, mutate the `Bindable<T>` values directly:

```cpp
void hud_sync_system(engine::ecs::World& world, HudViewModel& vm) {
    const auto& player_stats = world.ctx<PlayerStats>();

    // Updating the bindable automatically updates the UI text
    vm.healthText.set(std::format("{} HP", player_stats.current_health));
    vm.score.set(static_cast<float>(player_stats.score));
}
```

The engine dirty-checks bindables each frame during `Phase::Bind` and only re-measures layout when bound values change.
