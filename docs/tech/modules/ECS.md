# ECS

Homemade `ecs::World`: generational entities, sparse-set component pools, `ctx` resources, views, schedules, and double-buffered events. Camera and the 2D and 3D physics solvers sit on top of that world. There is no scene graph. Parenting is a separate `Parent` component with a derived `WorldTransform` (see Hierarchy); `Transform` has no parent field.

## Entities

`Entity` is an index plus a generation (`include/engine/ecs/entity.h`).

- `create` recycles a free index and bumps the generation.
- `destroy` during a view is deferred until the view depth returns to zero (`src/ecs/world.cpp`).
- `valid` is false after destroy. `try_get` returns null. `get` asserts.

Pools are a sparse index, a packed entity list, and a dense component array (`include/engine/ecs/world.inl`).

## Views and resources

`view<Ts...>()` requires at least one component. Iteration walks the smallest pool and skips entities missing any other type. `each` passes components by reference. A view holds `view_depth_` so destroy stays deferred.

`structure_version<T>()` is a structural signal, not change detection. It changes whenever a `T` is added to or removed from any entity, destroy included. Every pool is stamped from one counter per `World`, so a value never repeats within a world (destroying everything and building the same content again gives new values), and 0 means no `T` was ever added. Editing a `T` in place through `get` / `try_get` / a view does not change it. 2D physics uses it to notice collider adds and removes without walking the colliders.

`ctx<T>()` default-constructs one resource of type `T` per world. Engine code stores `Time`, `BoundWindows`, `ActiveCamera`, event cursors, and the localization `Catalog` this way. `ApplicationState` lives on `Worlds`, one per process. `WindowSizes`, `MouseConsumed`, and the pointer maps live on the process `Presentation`. `bind_presentation` stores a non-owning `ctx<Presentation*>`.

`window_size_for` reads `Presentation.sizes`. A hit inserts `Presentation.mouse`. `sync_frame` reads that same object. `ctx<ui::WindowSizes>()` and `ctx<ui::MouseConsumed>()` are separate. Resize, backfill, `window_size_for`, the hit-test, and `sync_frame` use the `Presentation` members.

## Schedules

`add_system(schedule, phase, fn)` appends a `std::function<void(World&)>`. `run` walks that schedule's phases in enum order, but only the phases listed in `kFixedPhases` or `kFramePhases`.

| Schedule | Phases |
| --- | --- |
| `Fixed` | `NetReceive`, `Physics`, `Game`, `NetSend` |
| `Frame` | `NetReceive`, `Input`, `Game`, `Transform`, `Bind`, `Audio`, `Render`, `UiRender` |

`Phase::Transform` is frame-only: the engine registers `update_world_transforms` there, after every `Game` system and before `Bind` and `Render`. `Phase::Physics` exists on the enum and is not a frame phase. `NetReceive` and `NetSend` hold the network systems, so a server tick brackets the whole fixed step and a client sees replicated state before its own frame systems; they stay empty unless the game calls `install_net_server` or `install_net_client` ([Net](Net.md#schedule)). `NetSend` is fixed-only. Game code that needs a one-shot click uses `Schedule::Frame` and `Phase::Game`. Physics uses `fixed_delta_time`. Which systems the engine registers: [Runtime Loop](../architecture/Runtime%20Loop.md).

## Events

`Events<T>` keeps two generations (`previous_` and `current_`). `World::flush_events` calls `update` on every queue: the previous generation is dropped and current becomes previous.

`EventWriter` sends into the live queue. Two readers:

| Constructor | What it sees |
| --- | --- |
| `EventReader(Events)` or `EventReader(World)` | every event still in the two-generation buffer, every time. A system that builds this every frame sees an event on the send frame and the next one |
| `EventReader(Events, EventCursor)` or `EventReader(World, cursor)` | events since `cursor.next_id`, then advances the cursor immediately. A cursor that fell behind the buffer is clamped; those events are gone |

The usual per-frame cursor is `ctx<EventCursor<T>>()`. A second independent reader holds its own `EventCursor`.

`flush_worlds` runs at the start of `GameLoop::tick` and `Host::tick`, before simulate. It flushes every world. `reentrant_tick` does not flush.

## Transform and camera

`Transform` is position, rotation, and scale. `rotation` is a unit `glm::quat`, identity by default. Scale defaults to `{1,1,1}`. `Transform` is always local: in world space for a root, in the parent's space for an entity with a `Parent`. `model_matrix(const Transform&)` (`include/engine/ecs/transform.h`) builds `T * mat4_cast(rotation) * S`.

Rotation helpers in `transform.h`:

| Function | Result |
| --- | --- |
| `rotation_z(radians)` | A turn about +Z. A 2D game sets rotation with it |
| `euler_xyz(vec3 radians)` | `Rx(x) * Ry(y) * Rz(z)`: Z applied first, then Y, then X |
| `angle_z(quat)` | The 2D angle back, in (-pi, pi]: the heading of the rotated +X axis in the XY plane. Exact inverse of `rotation_z`; 0 when that axis is on Z |

`Camera` (`include/engine/ecs/camera.h`, available in `namespace engine` and aliased in `namespace engine::ecs` along with `Projection`, `CameraProjection`, and `ActiveCamera`) looks down its local -Z with +Y up. `projection` is `Projection::Orthographic` (default) or `Projection::Perspective`. The defaults are the 2D camera, so a 2D game is unchanged.

| Field | Meaning |
| --- | --- |
| `ortho_size` | Orthographic: half-height in world units (default 10) |
| `fov_y` | Perspective: vertical field of view in radians (default 60 degrees) |
| `auto_aspect`, `aspect` | `auto_aspect` (default) rebuilds aspect from `WindowSize`; otherwise `aspect` |
| `near_clip`, `far_clip` | Default -1 and 1. Orthographic takes any range. Perspective needs `0 < near < far`, for example 0.1 and 1000 |

`projection_matrix` is `glm::ortho` from `ortho_size` or `glm::perspective(fov_y, aspect, near, far)`. A perspective near below `kMinPerspectiveNear` (0.01) is clamped up to it, a far not past near is clamped to `near + kMinPerspectiveNear`, and a warning is logged once per process. Clamping is not an error: a camera switched to perspective with the 2D clip defaults still draws.

`ActiveCamera` is a `ctx` resource holding one entity. `run_render` clears bound and `UiCanvas` window command buffers at the start of `Phase::Render`; when `ctx<BoundWindows>().ids` is empty, `run_render` returns before the camera check.

When the list is not empty, it returns when nothing is drawable. A drawable scene (any `Renderable`, `Sprite`, or `ParticleEmitter`) with an invalid or default `ActiveCamera` entity is fatal.

Fatal is also a live entity that lacks `Camera` or `Transform`. Either way that frame draws no world commands. A world with only UI needs no camera. `run_ui_render` still pushes `CmdDrawUI`. A window `run_render` already cleared is not cleared again. The view matrix is the inverse of the camera entity's world matrix (`ecs::world_matrix`), so a camera with a rotation or a `Parent` works. Each bound window gets one `render::CmdSetView` before its draws, with the same view matrix and camera position (the translation of that world matrix). Its projection is `window_size_for` for that id (`Presentation.sizes`). A `Renderable` or `Sprite` outside the `camera_frustum` of every bound window is not drawn ([Render](Render.md#frustum-culling)). For rendering an arbitrary `World` into a sub-rectangle of a window with an explicit camera (`WorldViewportRender`), call `render_world_viewport` (`include/engine/ecs/systems.h`; see [Render](Render.md#world-draw)).

Light components (`render::DirectionalLight`, `render::AmbientLight`) are plain data on entities; a directional light is aimed by its `Transform::rotation` and follows a `Parent`. Rules: [Render](Render.md#lights).

`view_matrix`, `screen_to_ray`, `screen_to_world` and `world_to_screen` take the camera's world matrix (`const glm::mat4&`, from `ecs::world_matrix(world, camera_entity)`), not its `Transform`. The last three also take the `Camera` and a `WindowSize`. Screen positions are window pixels, origin top-left, +Y down.

| Function | Result |
| --- | --- |
| `screen_to_ray(screen, camera, camera_world, window)` | A `Ray` (`include/engine/ecs/ray.h`: `origin`, unit `direction`) from the near plane away from the camera. Orthographic: every ray is parallel to the camera's forward. Perspective: through the pixel |
| `screen_to_world(screen, camera, camera_world, window)` | Orthographic: the point under the pixel halfway through the clip range (the camera's z for the default -1 and 1). Perspective: where `screen_to_ray` meets the world plane z = 0, which is what 2D-style picking expects; the ray's near-plane origin when the ray is parallel to that plane or the plane is behind the camera |
| `world_to_screen(world_pos, camera, camera_world, window)` | The pixel the point projects to, either projection |
| `camera_frustum(camera, camera_world, window)` | The world-space `render::Frustum` of that view (`include/engine/render/frustum.h`), the one `run_render` culls with ([Render](Render.md#frustum-culling)) |

### Ray queries

`include/engine/ecs/ray.h`, `src/ecs/ray.cpp`. Pure geometry: no world and no components. `t` is the parameter of `direction` (`point = origin + t * direction`). `screen_to_ray` produces a unit direction, so there `t` is a distance. A zero direction, a parallel ray, or `t < 0` is a miss for every half-line query. The hit normal is unit length and faces back along the ray.

| Function | Hit |
| --- | --- |
| `line_plane(ray, point, normal)` | The infinite line and the plane. `t` may be negative. nullopt when the line is parallel or `normal` is zero |
| `ray_plane(ray, point, normal)` | `line_plane` with `t >= 0` |
| `ray_sphere(ray, center, radius)` | The near surface. An origin inside the sphere reports `t = 0`. `radius < 0` misses |
| `ray_aabb(ray, min, max)` | The slab entry, in the ray's space. An origin inside the box reports `t = 0` and a normal of `-normalize(direction)`. A reversed bound is swapped. An oriented box is this after the ray is multiplied by the inverse world matrix; `t` is unchanged |
| `ray_triangle(ray, a, b, c)` | Either side of the triangle |
| `ray_quad(ray, a, b, c, d)` | Triangles ABC and ACD. Corners go around the boundary. The nearer `t` |
| `ray_segment(ray, start, direction, length, radius)` | The half-ray comes within `radius` of the segment. `direction` is normalized; `length` and `radius` are world units. `t` is the closest point on the normalized ray, not a surface entry |

`screen_to_world` for a perspective camera is `ray_plane` against the world plane z = 0, or the ray origin when that misses. `PointerTarget` hit-testing uses `line_plane` against the plane z of each target (a plane behind the camera still yields a point) and then the local rectangle, so it works under a perspective camera. For an unrotated orthographic camera that is the same point as before. The editor gizmo tests its center with `ray_sphere`, an axis with `ray_segment`, and a rotation ring with `ray_plane` plus a distance band.

## Pointer targets

`PointerTarget` is a component, not a callback: the entity's rectangle for the mouse. The input system reports hover, press, and click as `PointerTargetEvent` and as `hovered` / `pressed`, and counts the target for click-through itself. See [UI Input](../features/UI%20Input.md#pointer-targets).

## Hierarchy

`include/engine/ecs/hierarchy.h`, `src/ecs/hierarchy.cpp`. Not a scene graph: three components and free functions over `World`.

| Type | Role |
| --- | --- |
| `Parent{Entity entity}` | Plain data. The entity this one hangs from. Replicated state, together with `Transform`. |
| `Children{std::vector<Entity> entities}` | Derived index, the reverse of `Parent`. Only `set_parent`, `clear_parent` and destroy write it. |
| `WorldTransform{glm::mat4 matrix}` | Derived world matrix. Only `update_world_transforms` writes it. Never replicated. An entity gets one only while it has a `Parent`; roots use `model_matrix(Transform)`. |

The components live in namespace `engine` (like `Transform`). The functions that take a `World` live in `engine::ecs`.

Functions:

- `set_parent(world, child, parent, KeepWorld = No)` returns false and changes nothing for an invalid entity, `child == parent`, a cycle (`parent` is a descendant of `child`), or a result deeper than `kMaxHierarchyDepth` (32, root = 0, the child's own subtree counts). Setting the current parent again succeeds and does nothing. An entity without `Transform` is allowed as parent or child and counts as identity. Reparenting moves the child between `Children` lists.
- `KeepWorld::Yes` recomputes the child's local `Transform` from the exact world matrices so the world matrix does not change (`Transform` is created if the child had none). The matrix is decomposed into position, a rotation quaternion, and scale (a mirrored matrix puts the sign into `scale.x`). Skew caveat: a non-uniform scale above a rotated child gives a local matrix `Transform` cannot represent; the world position is kept exactly, rotation and scale are the best fit: the local X axis is kept, Y is made orthogonal to it, Z is their cross product, and scale is the length of each axis.
- `clear_parent(world, child, KeepWorld = No)` removes `Parent` and `WorldTransform` and takes the child out of its parent's `Children`.
- `world_matrix(world, e)`: `WorldTransform` if present, else `model_matrix(Transform)`, else identity. `compute_world_matrix` is the slow exact path that walks the `Parent` chain and ignores `WorldTransform`. `world_position` reads `world_matrix`. `set_world_position(world, e, p)` converts `p` into the parent's space (exact chain) and writes the local `Transform.position`.
- `update_world_transforms(world)` recomputes the whole forest every call, parents before children, idempotent. There are no dirty flags: `Transform` is a public struct that code mutates directly. It starts from the roots (entities with `Children` and no `Parent`), writes `WorldTransform` on every entity that has a `Parent`, and removes `WorldTransform` from entities that no longer have one. Deleting a `WorldTransform` and updating again gives the same matrix. Callers: the `Frame` / `Transform` system, `run_particles` at its start (it runs in `Game`, before `Transform`), and `run_physics_2d` and `run_physics_3d` after kinematic integration, after dynamic integration, and after the positional solve. Anything else that needs fresh matrices in between calls it too.

Destroying a parent destroys all its descendants (iterative, safe for deep chains), and destroying a child removes it from its parent's `Children`. `World::destroy_immediate` does this through `Children`, a deliberate small coupling of `world.cpp` to `hierarchy.h`. `destroy` inside a view is still deferred: the parent and its descendants stay alive and valid until the view ends, and then the cascade runs.

A `Parent` whose entity is dead can only come from hand-made data (the cascade prevents it). `update_world_transforms` logs one warning, removes that `Parent`, and the entity is a root from then on. `compute_world_matrix` stops its walk at a dead parent without logging.

Staleness contract: the engine refreshes `WorldTransform` in `Phase::Transform` (Frame) and inside `run_physics_2d`, `run_physics_3d`, and `run_particles`. A `Game` system sees the matrices of the previous frame's `Transform` phase plus whatever `run_particles` refreshed, so it should read `compute_world_matrix` or call `update_world_transforms` itself when it needs the result of an edit made this frame. `run_render` needs no refresh, because `Transform` precedes `Render`. `WorldTransform` is only as fresh as the last `update_world_transforms`. After a local `Transform` edit, `set_parent` or `set_world_position`, `world_matrix` still returns the old value until the next update; use `compute_world_matrix` for an exact answer now. `Parent` must be set through `set_parent`; a `Parent` that its parent's `Children` does not list is not visited by the update. A kinematic child's `RigidBody2D.velocity` is in the parent's space, because that body integrates the local `Transform.position`. A dynamic child's velocity is world XY; `run_physics_2d` writes it with `set_world_position`. The same split holds for `RigidBody3D`: kinematic velocity is parent space, dynamic velocity is world space and is written with `set_world_position`.

### Multiplayer readiness

`Transform` and `Parent` are the first two replicated components (slots 0 and 1 of `ReplicationRegistry`); a game adds its own with `register_replicated`. `WorldTransform` and `Children` are derived and rebuilt on the receiving side: the client applies `Parent` through `set_parent` / `clear_parent`. `Entity` handles (index + generation) are not stable across machines, so a replicated entity carries `engine::net::NetIdentity` (its `NetId`), `NetEntityMap` maps the id back to a local entity, and `Parent.entity` travels as the parent's `NetId` (`ReplicaWriter::write_entity`, `ReplicaReader::read_entity`). See [Net](Net.md#replicated-components).

## Physics

Physics is two solvers. The 2D one is `include/engine/ecs/physics_2d.h`. Its components, event and system carry a `2D` suffix (`RigidBody2D`, `BoxCollider2D`, `CircleCollider2D`, `PolygonCollider2D`, `CompoundCollider2D`, `SdfCollider2D`, `CollisionEvent2D`, `run_physics_2d`). The 3D solver adds its own types in `include/engine/ecs/physics_3d.h` (`RigidBody3D`, `BoxCollider3D`, `SphereCollider3D`, `CapsuleCollider3D`, `CollisionEvent3D`, `run_physics_3d`). They are not typedefs. `CollisionPhase` (`Enter`, `Stay`, `Exit`), `BodyType` (`Static`, `Kinematic`, `Dynamic`), and the shared step constants (`kMinDynamicMass`, `kContactSlop`, `kBounceThreshold`, `kPositionIterations`, `kSleepLinear`, `kSleepAngular`, `kSleepSteps`) live in `include/engine/ecs/physics.h`. `Physics2DConfig` stays in the 2D header. `RigidBody2D.angular_velocity` is radians per second about world +Z, default 0. `render::ParticleCollider2D` is the XY-only copy of box, circle, and SDF colliders that `run_particles` hands to `update_emitter`. Boxes and circles stay axis-aligned (box yaw is not copied); an `SdfCollider2D` is a non-owning view of its field at the entity's world position and yaw, skipped under a Dynamic body as the solver skips it ([Render](Render.md#sprites-animation-particles-curves)). The copy does not see `PolygonCollider2D` or `CompoundCollider2D`. `render::ParticleCollider3D` is the copy of non-trigger box, sphere, and capsule colliders, oriented by the world `Transform` quaternion. `ParticleGrid` is an optional world context (`try_ctx`); `collision_grid` sweeps it after the particle job joins. `run_physics_2d` integrates on the caller.

Physics is simulation and keeps to the [deterministic simulation](../architecture/Principles.md#deterministic-simulation) rules: same bits on every target. Shape and body angles become cosine and sine through `det_sin_cos`, matrix headings through `det_atan2` (`<engine/core/det_math.h>`), and `rotation_z`, `euler_xyz` and `angle_axis` (`transform.h`; the 3D integrator's spin) are built on them, never on libm or `glm::angleAxis`. `physics_state_hash_2d(world)` and `physics_state_hash_3d(world)` are FNV-1a 64 hashes of the solver state (each body in entity order: entity, type, Transform position and rotation, velocity, angular velocity, sleeping; then the warm-start contact cache and the sleep counters), for desync checks and the golden tests (`tests/simulation_golden_test.cpp`).

`Physics2DConfig` is a world resource, not a component. `world.ctx<Physics2DConfig>()` default-constructs it on first use (`Resource<T>::value{}`), so gravity starts at zero. Games set `gravity` there. It is not serialized.

`run_physics_2d` is the Fixed / Physics system. `dt` is `Time::fixed_delta_time`. The engine registers `run_physics_3d` right after it on the same phase; `run_fluid_2d` is opt-in (`install_fluid_2d`) and lands after both ([2D fluids](#2d-fluids)).

Before integration, a sleeping dynamic wakes when its linear speed is at least `kSleepLinear` (`0.05`) or `|angular_velocity|` is at least `kSleepAngular` (`0.05`). After the kinematic integrate and `update_world_transforms`, it also wakes when a real overlap (narrowphase, a touch included) exists with an awake dynamic or a kinematic whose linear or angular velocity is not exactly 0, and when the AABB of a collider on its own entity meets an SDF chunk that this tick's static re-read added, changed or dropped (see SDF colliders). Waking clears `sleeping` and the counter in `ctx<PhysicsSleepState2D>` (`physics_2d_internal.h`). That counter is not a component and is not serialized. `advance_sleep` (`src/ecs/physics_sleep.cpp`) steps it, and steps `ctx<PhysicsSleepState3D>` the same way. 2D passes `|angular_velocity|`; 3D passes `length(angular_velocity)`.

1. Kinematic bodies only: `local.position += velocity * dt`. `angular_velocity` is not integrated. Static bodies and dynamic bodies are skipped. The default type is kinematic, so an old body still tunnels.
2. `update_world_transforms`.
3. Dynamic bodies, outside any view. A dynamic with `sleeping` set is skipped: no gravity, no position write, and no yaw. Awake bodies do `velocity += gravity * gravity_scale * dt`, then `set_world_position` to `world_position + velocity * dt`. Targets are snapshotted first and written parents-before-children by hierarchy depth, so a dynamic parent does not drag a dynamic child. A kinematic or static parent has already moved, so that carry is in the snapshot. After every position write, each dynamic body yaws by `angular_velocity * dt`, still parents-before-children. A zero turn is skipped so an identity quaternion stays identity. A root does `rotation = rotation_z(dtheta) * rotation`. A child writes the same world-Z turn back into local rotation: `normalize(inverse(R_parent) * rotation_z(dtheta) * R_parent * R_local)`. The yaw write touches `Transform.rotation` only.
4. `update_world_transforms`.
5. Collect colliders at their **world position**. A collider is **movable** when the nearest `RigidBody2D` on its entity or above it is Dynamic or Kinematic, and **static** otherwise (no body, or a Static body). Movable colliders are gathered each tick by walking the Dynamic and Kinematic bodies and their descendants (down to the next `RigidBody2D`), once, after the kinematic integrate; the overlap wake uses that list, and the dynamic integrate only refreshes its pose. Static colliders are not gathered each tick: their items, AABBs, and AABB tree are cached in `ctx<PhysicsBroadphase2D>` (`physics_2d_internal.h`, `physics_2d_static.cpp`), so the cost of a tick follows the bodies and the contacts, not the static count. Static-static pairs are never queried. Each part of a `CompoundCollider2D` and each allocated chunk of an `SdfCollider2D` is its own cache slot and static-tree leaf, keyed by `(entity, shape, part)` (see Compound colliders and SDF colliders below). Movable colliders and static triggers go into the per-tick AABB tree in `src/ecs/broadphase.cpp` (rebuilt from the current bounds each step, closed bounds, no inflation; 2D proxies store z in `[-1, 1]`, so z never adds or drops a 2D pair) and each queries the cached static tree; only the statics they meet join the tick's collider list. That list is ordered by shape (boxes, circles, polygons, compound parts, SDF chunks), then `Entity`, then part index, and pairs are sorted by that order before publish.
   The static cache is rebuilt the next tick, with nothing for the game to do, when a `BoxCollider2D`, `CircleCollider2D`, `PolygonCollider2D`, `CompoundCollider2D`, or `SdfCollider2D` is added or removed anywhere or an entity is destroyed (`World::structure_version`), and when an entity enters or leaves the movable set (a `RigidBody2D` added, removed, or retyped; a collider parented under a moving body or cleared from it). **Editing static geometry in place is not noticed**: after changing the `Transform` of a static collider or of any ancestor, its collider fields, or its `Parent`, mark it (`physics_2d.h`) and the next tick sees it. `mark_static_colliders_dirty_2d(world, entity)` re-reads only the static colliders on `entity` and on all of its descendants (the whole subtree is walked, since an ancestor's `Transform` moves it; colliders in the movable set are skipped), replaces only their cache slots and keys, and inserts, removes, or updates only their static-tree leaves, so a compound that grew or shrank changes its slot count. The keys, `static_entities`, and the static triggers keep the order a full re-read gives, so the tick (collider order, pairs, events, solver) is the same either way. Several per-entity marks in one tick are one re-read. A dead entity is not recorded, and an entity with no static collider in its subtree re-reads nothing. `mark_static_colliders_dirty_2d(world)` re-reads every static collider, for bulk edits whose entities are not known; when it is pending, or any of the automatic triggers above fired, the full re-read runs instead of the per-entity one and covers the marks. A forgotten call is caught by an audit that re-reads 32 cached statics per tick, round robin (about `N / 32` ticks for `N` statics; a compound part or an SDF chunk counts as one; a compound part also compares the shape count it was read with, so a compound that grew or shrank in place is found too, and an SDF chunk compares the field's `edit_count`, so any edit of the field, a new chunk included, is found from any of its slots); it rebuilds the cache and logs one warning per entity. The per-entity re-read runs before the audit, so a marked edit is never reported. Geometry that moves every tick should carry a Kinematic body (it is then movable and never cached). A full rebuild re-reads every static collider (about 0.7 ms at 2,000 in RelWithDebInfo; a tick after a per-entity mark of one of those cells costs about 50 us against 35 us idle) and edits the static AABB tree only where a collider was added, removed, or changed; any collider add or remove, a spawned projectile included, costs one such re-read that tick ([Physics Bench](../features/Physics%20Bench.md)). Replication or a serializer read that overwrites a static's components in place is an in-place edit too. The narrowphase still rejects misses. A shared face is a candidate. A sleeping body still publishes. A collider on a child follows its parent. Scale is not applied to `size`, `radius`, or polygon vertices. The collider angle is `atan2` of the cached world matrix (`world_matrix`) X axis in XY (the same epsilon as `angle_z`), read right after `update_world_transforms`. A circle ignores that angle. A box whose angle is exactly `0` stays on the legacy AABB manifold. Any other box angle, and every polygon, uses the convex clipper in `contact_2d_polygon.cpp`. Polygon vertices are local, CCW, at most `kPolygonCollider2DCapacity` (8), and are not recentered; the world polygon is center plus one yaw. Fewer than 3 vertices, a non-finite component, a zero-length edge, a clockwise turn, or a non-positive area produces no contact. A collinear turn is kept. Two colliders on one entity are not a pair. Publish one event per entity pair per tick: when the two entities touch through several shape pairs (compound parts, or several colliders on one entity), `normal`, `penetration`, `point`, and `is_trigger` come from the deepest shape pair (largest `points[0].penetration`), and equal depth keeps the earlier pair in the collider order. The event goes out in the order of the pair's first shape pair, through the reusable scratch `PhysicsOverlapState::pending`. 3D keeps the first manifold (see 3D physics). Publish Enter, Stay, and Exit from this pre-solve pose. The event stores `points[0]` only: the deeper point, or the midpoint when the two clip depths compare equal (the count collapses to 1). Overlap memory is `ctx<PhysicsOverlapState>` (the ordered pair and whether it was a trigger). A separation the solver creates this step still reports Enter or Stay; Exit is the next step with `count == 0`. Slop is not an event threshold. There is no Z test.
6. Solver candidates use that same tree, then the same filters, then the canonical `(min(Entity), max(Entity), shape, part, item)` sort. Real overlaps are partitioned into independent color sets (`src/ecs/contact_graph_coloring.cpp`, up to 24 colors plus an overflow bucket) so no two contacts in the same color share a writable awake dynamic body. Within each iteration, colors execute sequentially in canonical order while contacts inside each color run concurrently across `JobSystem::parallel_for` without atomics or locks (overflow runs serially at the end of the iteration). Because constraints within a color are mutually independent, results are bit-deterministic regardless of worker thread count. A sleeping dynamic enters with inverse mass 0, inverse inertia 0, and solver velocity 0. The solver does not write that zero velocity back over the component. `solve_position_iteration_2d` (`src/ecs/solver_2d.cpp`) is a pure function: bodies and an impulse accumulator in, corrections out, no `World` and no events. The system applies `set_world_position` and writes dynamic `velocity.xy` and `angular_velocity`. Kinematic and static `angular_velocity` are copied into the solver (so a kinematic point velocity includes spin) and are not written back. Inverse inertia is 0 for both. The accumulator seed is `ctx<PhysicsContactCache2D>` (`physics_2d_internal.h`), keyed per shape pair: `ContactCacheKey2D` is the two entities (lower first), the `ColliderShape2D` of each side, and the part index of each side, so two compound parts (or two colliders) touching the same body warm-start separately. The shape angle is sampled at gather and held fixed for the iterations.
7. Before the iterations, each overlapping pair whose cached normal still agrees with the current manifold (`dot > 0`) copies the two per-point impulses into the accumulator, point i into point i. A flipped normal (`dot <= 0`) drops both. The seed is not applied to velocity. The cache stores two impulses per pair and is replaced after the iterations by pairs that overlapped. An empty candidate list clears it. The cache is not serialized. The iteration recomputes the delta from the current relative velocity and clamps it against the seed. `kPositionIterations` (8) times: refresh transforms, copy world XY into the body cache, recompute `make_contact_2d`. Positional correction stays the mass-only push from `points[0]`: `depth = max(0, penetration - kContactSlop)`, `inv = inv_m_a + inv_m_b` (not `inv_n`). A positive `inv` and `depth` move A by `-n * depth * inv_a / inv` and B by `+n * depth * inv_b / inv`. The tangent is `t = (-n.y, n.x)`. Relative velocity at a point includes spin. Friction is `sqrt(fa * fb)` after each friction is clamped to `>= 0` (negative or non-finite is 0). Restitution is `max(ra, rb)` after each restitution is clamped to `[0, 1]` (non-finite is 0). The component values are not written back. If `v_rel_n >= -kBounceThreshold` (`1`), restitution is 0 for that impulse, so a resting body under gravity `(0, -60)` approaches at exactly 1 and does not bounce. If `inv == 0` the velocity step is skipped. Each contact point then takes its own impulse. `r` is `point - body position` captured before the positional push. `v_point = v_linear + omega * (-r.y, r.x)`. `rn = r.x * n.y - r.y * n.x` and `rt = r.x * t.y - r.y * t.x`. `inv_n = inv_m_a + inv_m_b + rn_a^2 * inv_I_a + rn_b^2 * inv_I_b`, and `inv_t` is the same with `rt`. `j_n = -(1 + e) * v_rel_n / inv_n` when `v_rel_n < 0`, else 0, accumulated per point and clamped at 0. `j_t = -v_rel_t / inv_t`, then that point's tangent accumulator is clamped to `[-mu * that point's accumulated normal, +mu * it]`. Both points are full weight: there is no one-half factor. `omega_a -= lever * j * inv_I_a` and `omega_b += lever * j * inv_I_b` for the normal (`rn`) and the tangent (`rt`). Only a dynamic body is written. Static inverse mass is 0 and its velocity is treated as 0. Kinematic inverse mass is 0 and its velocity is not written. A root kinematic's `velocity.xy` is world XY. A kinematic with a parent contributes `world_matrix(parent) * vec4(velocity, 0)` XY, which is the parent's linear map (rotation and scale included), matching `T * R * S`. The kinematic's own rotation is not applied. Writes go out parents-before-children by depth. After the iterations the cache is replaced by the pairs that overlapped in at least one iteration (final accumulator and that hit's normal). Pairs that did not contact, and a step with no candidate pairs, drop their entries. Because the cache is not added to velocity again, a resting contact's normal accumulator grows by about the new `j_n` each step and the friction cone widens with it. Coulomb friction therefore removes about `mu * |g| * dt` of tangent speed per resting step.
8. `update_world_transforms` once more so later systems see the solved pose.

After the velocity write, a dynamic whose linear speed is below `kSleepLinear` and whose `|angular_velocity|` is below `kSleepAngular`, and that has at least one solver manifold, increments the ctx counter (clamped at `kSleepSteps`, 8). Reaching 8 sets `sleeping`. Otherwise the counter is cleared, and `sleeping` is cleared when either speed is at or above the threshold. No solver contact does not start sleep, and a dynamic with no touched solver contact this step, a sleeper included, has `sleeping` cleared (`update_sleep_2d`), so a sleeper whose ground disappears wakes at the end of that step. `RigidBody2D.sleeping` is the last field and is serialized. A missing key loads false. Kinematic and static bodies ignore the flag.

Inverse mass of a dynamic body is `1 / m` with `m = mass > kMinDynamicMass ? mass : kMinDynamicMass`. Inverse inertia is `1 / I` for a dynamic body and 0 otherwise. `I` is computed once, from the first non-trigger collider in gather order (boxes, then circles, then polygons), even when that `I` is 0. Extra colliders still generate contacts. They do not contribute another full mass. A `CompoundCollider2D` never reaches this: under a Dynamic body it is left out. A box uses `m * (width^2 + height^2) / 12` with the full size. A circle uses `0.5 * m * radius^2`. A polygon uses `m * sum(D * (x0^2 + x0*x1 + x1^2 + y0^2 + y0*y1 + y1^2)) / (6 * sum(D))` with `D = x0*y1 - y0*x1` over the edges, about the vertex-list origin (an off-center polygon is not recentered). `make_contact_2d` (`src/ecs/contact_2d.cpp`) keeps the legacy one-point manifold when both boxes have angle exactly 0, when both shapes are circles, or when an angle-0 box meets a circle: X wins a tie, a penetration of 0 is a touch, and a non-finite or negative size returns an empty manifold. Do not give a predicted or controlled entity a `RigidBody2D` ([Net](Net.md)). `run_physics_2d` is outside prediction `step`, so a kinematic body still integrates and a dynamic body is solved there. An entity with `RigidBody3D` is skipped by the 2D integrator and by 2D pair tests (events and the solver) through `claimed_by_physics_3d` (`src/ecs/physics_owner.cpp`), so it is not moved twice. Do not put both rigid bodies on one entity.

### Compound colliders

`CompoundCollider2D` (`physics_2d.h`) puts many convex shapes on one entity, so chunked terrain (one 32x32 tilemap chunk, one marching-squares chunk) is one entity instead of one per cell. Every ECS pass that walks colliders or the hierarchy then pays per chunk, not per cell ([Physics Bench](../features/Physics%20Bench.md)).

- `shapes` is a `std::vector<CompoundShape2D>`; each shape is a convex polygon of at most `kPolygonCollider2DCapacity` (8) vertices, CCW, in the entity's local XY about its origin, not recentered and not scaled, with the validity rules of `PolygonCollider2D`. `box_shape_2d(center, size, angle)` builds a box as a 4-vertex shape. Boxes are polygons here, so an angle-0 compound box uses the convex clipper, not the legacy AABB manifold. There is no cap on the shape count.
- One material per component: `layer`, `mask`, `friction`, `restitution` apply to every shape. No `is_trigger`: static triggers are queried every tick, so trigger regions stay separate entities.
- Where it is supported: static (no body, or a `Static` body), and under a `Kinematic` body, where the parts are movable colliders gathered every tick like any other. Under a `Dynamic` body (on the entity or above it) the compound is left out entirely, not cached as static either, and `log::warn` fires once per entity. Dynamic compounds (mass, inertia, centroid) are future work.
- Internally a part is a `ColliderItem2D` with `ColliderShape2D::Compound` and its index in `part`; every shape function treats it as a polygon at the entity's pose. Static parts expand into one cache slot and one static-tree leaf each, owned by one entity (`static_entities` lists it once).
- Adding or removing the component is noticed through `structure_version<CompoundCollider2D>()`. Editing `shapes` (or `layer`, ...) in place is an in-place static edit: call `mark_static_colliders_dirty_2d(world, chunk)`. That re-reads only the chunk's parts (and its descendants'), so a chunk edit costs the chunk, not the map. Its slot count follows `shapes.size()`: parts past the old count get new slots and leaves, parts past the new count drop theirs, and a chunk with no shapes left is no longer in `static_entities`. The world-wide mark re-reads every static part.
- Events and contact cache: see steps 5 and 7 above. A dynamic body sliding across the parts of one compound stays one Stay stream, with no Exit or Enter per part.
- Grid queries and ray queries are pure math and do not read colliders, so they need no compound support. `run_particles` does not see compound shapes.

### SDF colliders

`SdfCollider2D` (`physics_2d.h`) is an `SdfField2D` (see [SDF fields](#sdf-fields)) the 2D solver collides with: destructible terrain that a game carves and fills in place. Narrowphase in `src/ecs/contact_2d_sdf.cpp`; gather, cache and wake beside the compound code.

- `field`, `layer`, `mask`, `friction`, `restitution`; no trigger. The field is in the entity's local XY: the entity's world position and yaw (`atan2` of the world matrix X axis, as for every collider) apply, scale does not.
- Supported like `CompoundCollider2D`: static, or under a `Kinematic` body (gathered every tick); under a `Dynamic` body it is left out with one `log::warn` per entity (`dynamic_terrain_warned`, shared with compounds).
- Parts: one `ColliderItem2D` with `ColliderShape2D::Sdf` per **allocated** chunk, whatever it holds (a chunk of all-air or all-solid samples costs a slot and reads nothing). `part` encodes the chunk, `(cy + 32768) << 16 | (cx + 32768)`, so part order is `chunk_coords` order (y, then x); a chunk outside `[-32768, 32767]` on either axis (about a million cells from the origin) has no part. The item's polygon is the chunk's cell rectangle grown by 1/100 of a cell, which is only its AABB; the item also stores the chunk's `revision`, and the slot stores the field's `edit_count` as its audit stamp. The item's field pointer is never kept from the cache: it is refreshed from the component whenever the item joins a tick's collider list.
- A body touches the field only through allocated chunks. Unallocated space reads `outside`; with `SdfOutside::Solid` a body there is inside solid, but no chunk owns its samples, so it gets no contact (an unallocated `Solid` region is not a collider). An `SdfCollider2D` with no allocated chunk has no slot, so the audit cannot notice its first edit: mark it.
- Contact, body against one chunk. A sample counts for the chunk that owns the cell it lies in, so a body over a seam gets each sample once, split over the chunks' pairs. Circle: its center, `d = sample(center)`; a contact when `d <= radius`, normal `-gradient` (from the body into the solid; the manifold normal is from shape a toward shape b, so it flips when the field is a), penetration `radius - d`, point halfway between the surface point `center - n d` and the circle's deepest point. Box or polygon (convex, CCW, the polygon rules; boxes of any angle): its vertices and points along each edge at most one cell apart (`ceil(length / cell_size)` per edge, at most 64), read in one `sample_many`; samples with `d <= 0` penetrate. The manifold's `points[0]` is the deepest (the first in outline order on a tie) with the normal from the gradient there; `points[1]`, when there is one, is the penetrating sample farthest from it along the surface tangent, with its own depth, so a flat face resting on the field gets two points at its corners. Points lie halfway between the sample and the surface along the normal. A zero gradient (deeper than `band`, where the field is flat) is no contact, so penetration is bounded by the band; a field feature thinner than the sample spacing can slip between samples, and one wholly inside a body's outline is not seen. Field against field is no contact. Pair filters are the usual ones: static-static never pairs, a kinematic field against static colliders publishes events like a kinematic compound.
- Events and contact cache: the cache key's part is the chunk, so warm start survives while a contact stays in one chunk; events stay one stream per entity pair (deepest wins), so sliding across a seam is one Stay stream with no Exit or Enter.
- In-place edits: `structure_version<SdfCollider2D>()` notices adding or removing the component. Editing the field (`carve_*`, `fill_*`, `fill_from_mask`, `renormalize`, `assign_chunk`) is an in-place static edit: `mark_static_colliders_dirty_2d(world, entity)`. The re-read builds the entity's chunk items (coordinates and revision, no samples) and merges them with its slots: a chunk whose revision, pose and material did not change keeps its slot and leaf, a new chunk gets a slot, and `last_rebuild_changes` counts what moved. Without a mark the audit finds the changed `edit_count` within `N / 32` ticks and warns. Once the cache has been built, every SDF slot a re-read adds, changes or drops (the per-entity one, the full one, or the audit's) queues its old and new bounds in `sdf_wake_boxes`; that tick, before the dynamic integrate, `wake_sleepers_by_static_edit_2d` wakes the sleeping dynamics whose own collider AABB meets one of them. A sleeper that lost all contact would wake at the end of the step anyway; this wake covers the one that still touches (half its ledge carved away). Compound and other static edits do not queue a wake.
- Serialized as `sdf_collider_2d` (World serialization below). Not registered for network replication ([Net](Net.md)): the field is large and edits are few, so a game replicates its edit calls (carve and fill with their arguments) and applies them on every peer, then marks.
- Particles: `run_particles` copies every `SdfCollider2D` not under a Dynamic body into a `ParticleCollider2D` with `Shape::Sdf` (the field pointer, world position and yaw, `layer`); the emitter's `collision_mask`, `bounce` and `friction` apply, not the collider's `mask`, `friction` or `restitution`. Unlike the solver, particles read unallocated `Solid` space too, but it is flat (`-band`, no gradient), so a particle there gets no contact either. See [Render](Render.md#sprites-animation-particles-curves).
- Cost: an idle field is one slot per chunk and costs what idle compound chunks cost; a contact reads 16 points for a unit box on 0.25-unit cells per evaluation, about 11 evaluations a tick. See [Physics Bench](../features/Physics%20Bench.md#sdf-terrain-lq-26).

### 2D fluids

`Fluid2D` (`include/engine/ecs/fluid_2d.h`, `src/ecs/fluid_2d.cpp`, private `src/ecs/fluid_2d_internal.h`) is a liquid of Position Based Fluids particles (Macklin and Mueller 2013) in world XY. `run_fluid_2d(world, jobs)` steps every `Fluid2D` by `Time::fixed_delta_time`, with gravity `Physics2DConfig::gravity` (XY) times `gravity_scale`. Rendering is out of scope: a game draws `positions()` (and can shade by `velocities()` or `densities()`) with its own sprites or particles.

- Opt-in: `register_simulation_systems` does not step fluids. `install_fluid_2d(world, jobs)` registers `run_fluid_2d` on Fixed / Physics once per world and keeps a private `FluidInstall2D` marker in `ctx` (`src/ecs/fluid_2d_internal.h`) holding `jobs`, which the system reads each tick; a second call replaces `jobs` and adds no system. Called before the simulation systems are registered (a game's constructor: `GameBase` creates its world before `Worlds::set_deps`), it only leaves the marker, and `register_simulation_systems` adds the system right after `run_physics_3d`. Called after (`on_start`, or any later setup), it appends the system to Fixed / Physics at once: after `run_physics_2d` and `run_physics_3d`, and after any Physics system the game added earlier. Either way it runs after both physics steps, so it bounds against this tick's collider positions. Without the install a `Fluid2D` keeps its particles and never moves. There is no warning for that: detecting it would need a check on every world every tick, which is the cost the opt-in removes. A bench or tool may call `run_fluid_2d` directly on a world without the install.
- API: `Fluid2D` holds `params` (`Fluid2DParams`) and owns the particles. `spawn(position, velocity)` adds one (false at `max_particles` or for a non-finite input); `spawn_box(min, max, velocity)` fills a rectangle on a square lattice at the rest spacing (2 `radius`), row by row from the bottom, and returns how many it added; `clear()` drops all; `count()`; read-only spans `positions()`, `velocities()`, `densities()` (density over rest density from the last iteration). Particle order is spawn order; only a drain removes particles, and the others keep their order. The entity needs no `Transform`.
- Sources, drains, sensors and queries (LQ-60): `FluidRegion2D` is an axis-aligned box (`center`, `half_extents`) or a circle (`center`, `radius`) in world XY, with `contains` and `area`. `Fluid2D::sources`, `drains` and `sensors` are plain vectors next to `params`. `run_fluid_2d` emits for every fluid first (the reach and boundaries see the new particles), then steps them, applies the coupling, then drains and senses each fluid. A `FluidSource2D` owes `carry + rate * dt` particles a tick and emits the whole part, keeping the fraction in `carry`; point `emitted` of the R2 low-discrepancy sequence (fractional parts of `0.5 + n / g` and `0.5 + n / g^2` for the plastic number g, in double, so the same on every peer) places each one, over a box directly and over a circle by area (radius `sqrt(u)`, angle `2 pi v` through `det_sin_cos`), with the source's `velocity`. Emission stops at `max_particles` and the rest of that tick is dropped, not queued. A `FluidDrain2D` removes, after the step, every particle inside it (the first enabled drain that holds a particle counts it in `drained`), compacting the arrays in order. A `FluidSensor2D` measures `fill`, the particles inside times `(2 radius)^2` over the region's area, after the drains; it turns `full` at `threshold` and back below `threshold - hysteresis`, and each change sends a `FluidSensorEvent2D` (`fluid`, `sensor` index, `full`, `fill`, `count`) through the world's double-buffered events. Queries read the particles as the last step, spawn or drain left them: `query(region)` and `query(polygon)` (a simple polygon, either winding, even-odd rule) return a `FluidQuery2D` (count, `volume` = count times `(2 radius)^2`, mean velocity); `is_wet(point)` is true when a particle center is within the rest spacing. They share a lookup grid (cells of two radii, a counting sort into a power-of-two hash, like the solver's neighbour search) that the first query after a change builds and that the solver step, `spawn`, `clear` and the drains invalidate; a query reads only the cells under its bounds, or every particle when that is fewer. `state_hash` covers each source's `carry` and `emitted` and each sensor's `full`, since they decide what happens next; drain counts and fills are outputs. The settings (regions, rate, velocity, enabled, threshold, hysteresis) are serialized with `fluid_2d` as arrays of tables `sources`, `drains` and `sensors` (a region is `shape` "box" or "circle", `center`, and `half_extents` or `radius`); the state is not.
- Parameters: `radius` (0.05; the boundary clearance and half the rest spacing), `smoothing_length` h (0: 6 radii, 3 rest spacings, about 24 neighbours at rest), `rest_density` (0: the poly6 density of the `spawn_box` lattice, so a spawned block starts at rest), `viscosity` (XSPH c, 0.1), `relaxation` (the CFM epsilon, 0.5), `tensile_strength` (s_corr k, 0.005), `iterations` (4, clamped to [1, 32]), `substeps` (2, clamped to [1, 16]), `max_particles` (16384), `gravity_scale` (1), `density` (1, coupling), `cohesion` (0), `vorticity` (0), `friction` (0.1) and `restitution` (0), both clamped to [0, 1], `layer` and `mask`. Non-finite or non-positive sizes fall back to the defaults.
- Units: the solver divides every particle offset by h, uses the h = 1 kernels (2D poly6 `4/pi (1 - r^2)^3` for density and XSPH, the 2D spiky gradient `-30/pi (1 - r)^2` for the constraint) with unit mass, and multiplies position deltas by h on the way back. `rest_density`, `relaxation` and `tensile_strength` are in these units, so a tuning holds at any world scale for the same particles per h and substeps per second. The paper's s_corr k = 0.1 is for its units: here 0.005 lets a resting pool come to rest, below about 0.003 (or with `viscosity` under about 0.05) it keeps jittering, and from about 0.01 it visibly expands.
- Substep (`substeps` per tick): `v += g dt`, predict `p = x + v dt`; neighbour search on `p`; `iterations` times lambda, delta, then apply and project onto the boundaries; velocity `(p - x) / dt` and the boundary response; XSPH; `x = p`. The density constraint is one-sided, `C = rho / rho_0 - 1` only when positive (only compression pushes; a free surface does not pull), with `lambda = -C / (sum |grad C|^2 + relaxation)`. The delta gathers `(lambda_i + lambda_j + s_corr) grad W / rho_0` over the neighbours, s_corr `-k (W(r) / W(0.2 h))^4`, and is clamped to one radius per iteration, so a deep overlap (a spawn on top of another particle, a collider moved into the fluid) spreads over several iterations instead of exploding. XSPH adds `c sum (v_j - v_i) W / rho_0`. Cohesion and vorticity confinement (LQ-58, both off by default, then their passes are skipped and the result is unchanged) act on the same velocity pass. Cohesion (Akinci et al. 2013, the cohesion term) adds `-cohesion h dt sum_j K_ij C(r) r_hat`, `K_ij = 2 / (rho_i + rho_j)` in rest-density ratios and `C` Akinci's spline at h = 1 (times its `32 / pi`: attraction beyond half the support, a slight repulsion closer), so a particle with fewer neighbours, at the free surface, is pulled in: a surface tension that rounds blobs and keeps falling drops together. Akinci's curvature term `n_i - n_j` is left out: explicit in this solver it throws out the corners of a block, with either sign. Vorticity confinement (Macklin and Mueller 2013) first gathers each particle's SPH curl `w_i = sum_j grad_i W_ij x (v_j - v_i) / rho_0 / h` (1/s, from the velocities after the boundary response), then adds `vorticity dt (N x w_i)` with `N` the unit SPH gradient of `|w|`, `sum_j (|w_j| - |w_i|) grad_i W_ij`. Both are gathers. Tested ranges (`Fluid2DCohesion`, `Fluid2DVorticity`): cohesion 4 to 16 lets a pool come to rest, 64 holds an 8 x 8 drop within its starting size over a second of fall (0.5 against 1.8 without) with a pool shimmering slightly; vorticity 0.05 keeps a free vortex turning (99.4 percent of its angular momentum over 2 seconds against 97.8 percent without), 0.1 still lets a pool rest, and from about 0.2 a free vortex gains angular momentum.
- Neighbours: a spatial hash with cell h (a power-of-two table of at least twice the particle count, so a particle far away costs nothing), filled by a stable counting sort, so a bucket lists its particles in index order. Each particle scans its 3 x 3 cells (dy, then dx) and keeps the particles in exactly that cell (two cells sharing a bucket are not counted twice) closer than h, at most 48 (`kFluidMaxNeighbors2D`; about 24 at rest, the cap only bites under heavy compression). Searched once per substep; the lambda pass keeps each neighbour's kernel weight and gradient (one 16-byte record per slot) for the delta pass, which reads the same positions. The candidate test is branch-free, and a group of four particles' lists is padded to the longest of them with the particle itself (slots past the count are never summed). With sleepers (below) there are two hashes, the awake particles' at their predicted positions per substep and the sleepers' once per step, and a list holds the awake candidates of the 3 x 3 cells, then the sleeping ones; with none asleep it is the single hash's list.
- SIMD (LQ-55): on x64 the lambda pass runs four particles per SSE2 register, each lane running the scalar loop's operations in its order (SSE never contracts a multiply and an add), so a lane's result is the scalar one bit for bit; wasm and arm64 run the scalar loop. `set_fluid_scalar_kernels_2d` (private, `fluid_2d_internal.h`) runs the scalar loop on x64 for tests. Work is split in ranges of 64 particles.
- Sleeping (LQ-38, `Fluid2DParams::sleep`, off by default): a particle whose step moves it less than `sleep_speed` (radii per second, 0.5) times `dt`, for `sleep_ticks` (60) fixed ticks in a row, falls asleep: its velocity becomes zero and it is no longer solved. The step's displacement and not the velocity: a resting particle's velocity is the noise of its last substep's boundary response and crosses that threshold now and then, its displacement stays a fraction of it. Sleep state is per particle (`sleeping()`, `sleeping_count()`), with a saturating rest counter.
  - Solve: each pass runs over `order`, the awake particles in group order and then the sleepers some awake particle lists this substep, in group order. Those sleepers take part in the lambda pass with their full neighbour lists (the lambdas of both ends push an awake particle, as in the full solve) and in the curl, but are not moved, swept, projected or given a velocity; a sleeper beyond them is only read, as their neighbour, at its position. So an awake particle meets the sleepers as the neighbours they are and a sleeper never drifts. The sleepers' hash is built once per step and kept across steps while the same sleepers sit at the same positions (a cache keyed by each member's `sleep_stamp_`, a process-wide number renewed whenever its particle arrays or its set of sleepers change; a kept hash is the one a rebuild would give). Boundary selection, coupling and contact events (pairs with at least one awake particle) read the awake particles only. A group with no awake particle skips its step.
  - Wake: (1) after the step, a listed sleeper that an awake neighbour of the last substep moved past faster than the sleeper's `wake_speed` (radii per second, 4, at least `sleep_speed`), measured the same way; (2) before the step, every particle within a kernel support plus a radius of the box of a collider on a Dynamic or Kinematic body (and of a source that emitted this tick) is held awake for the step and counts no rest, so a body moving into a sleeping pool meets awake water and a floating body keeps its water awake; (3) static boundaries: while a particle sleeps or can fall asleep this step, the fluid keeps marks of what bounds it within its box grown by h plus a radius, a 64-bit key of the content with its world box per static shape and per block of 8 x 8 samples of every allocated SDF chunk (one more per field that is solid outside), and before each step wakes the sleepers within h plus a radius of every mark that appeared or went away (a collider added, moved or removed, terrain carved or filled, a field moved); (4) a drain that removed a particle wakes the sleepers within h plus a radius of its region; (5) a change of gravity (times `gravity_scale`) or of the resolved parameters wakes the whole fluid; (6) `wake()` and `wake(region)`; turning `sleep` off wakes every particle on the next step. A new particle (`spawn`, a source) is awake.
  - Determinism: every decision is a gather over the particle's own slots or serial in particle order, and the set of sleepers an awake particle lists is flagged with relaxed stores of 1 from any range (the same set whatever the scheduling), so the bits are the same for any worker count and with the scalar or SIMD kernels (`Fluid2DSleep.ThreeJobsAndScalarKernelsGiveTheSameBitsAsSerial`). The rest counters, the sleep flags and the marks are simulation state: in `save_state` and, with `sleep` on, in `state_hash` (without it they are all zero and left out, so a fluid that does not sleep hashes as before LQ-38).
  - Why off by default: on, the golden dam break changes (its pool starts to fall asleep) and a box at 2 percent of the water's density bobs higher (`Fluid2DCoupling.VeryLightBodyBobsButStaysInThePool` passes its bound of 4 units by 0.04); a flow slower than `sleep_speed` stops, and a pool that falls asleep mid-slosh keeps that surface until something wakes it. A game turns it on per fluid for pools that settle.
  - Tested (`Fluid2DSleep`): a dam break in a 3-unit tank falls asleep, as high and as level as the same pool awake, and then keeps its bits; a woken column between sleepers neither jitters nor drifts and sleeps again; a dropped box wakes the pool, splashes and floats; a save and load in the middle of falling asleep steps on with the same hash every tick; three jobs and the scalar kernels give the serial bits through falling asleep and a splash; a carve wakes what is near it and the water runs into the pit while the far end sleeps on; removing a static wall lets the water it held flow; a static circle placed in a sleeping pool pushes it out; a drain empties a sleeping pool and a tap wakes it; gravity, the flag and `wake` wake it; it is off by default. `NetFluidSync.ASleepingFluidStaysTheSameOnEveryPeer` keeps two clients (one joining a mostly sleeping pool) on the server's hash through a carve, and the golden `SimulationGolden.SleepingPoolMatchesGoldenForAnyWorkerCount` pins the sleep path on every target.
- Determinism: same bits on every target ([Principles](../architecture/Principles.md#deterministic-simulation)); a collider's frame comes from its matrix's normalized X axis, with no angle. `state_hash()` is the FNV-1a 64 hash of the particle count and every position and velocity (bits, spawn order), and with `sleep` on the sleep state (above), for desync checks; the golden dam break in `tests/simulation_golden_test.cpp` pins it. Every per-particle pass (predict, neighbour lists, lambda, delta, apply and project, velocity, XSPH) is a gather: particle i writes only its own slots and reads the previous pass's buffers, so the `parallel_for` ranges (64 particles) give bit-identical results for any worker count; the hash fill and the fluid's AABB are serial. Positions are not reordered for cache locality, which keeps particle identity stable.
- Boundaries: no `CollisionEvent2D`; only Dynamic bodies are pushed back (two-way coupling, below). Colliders are gathered once per tick after `run_physics_2d` (its last `update_world_transforms`), at their world position and yaw, and bound a fluid under the solver's rule `fluid.mask & collider.layer` and `collider.mask & fluid.layer`. Per substep the shape list (boxes, circles, polygons) is cut to those whose AABB meets the fluid's predicted AABB grown by a radius plus, per iteration, the delta clamp and a radius (an SDF push); every matching SDF field stays (its `allocated_bounds` rejects per particle, except with `SdfOutside::Solid`). The kept shapes go into a per-substep grid (`ShapeGrid2D`, cells of two kernel supports, a shape in every cell its AABB grown by a radius covers within the fluid's box, each cell in selection order, a counting sort like the neighbour hash), and a particle projects only against the shapes of its cell, so terrain made of many compound parts costs a particle what is near it.
  - Polygons (LQ-57): `PolygonCollider2D` (static, kinematic or dynamic) and each `CompoundCollider2D` part (static or under a Kinematic body; skipped under a Dynamic body, as the solver skips it) become world-space convex polygons, from the solver's own items (`make_polygon_item_2d`, `make_compound_item_2d`, `contact_shape_of_2d`) under the solver's rules (3 or more vertices, finite, no zero-length edge, no clockwise turn). Static ones come from the 2D solver's static cache: `run_fluid_2d` bounds where any fluid can be this tick (`fluid_reach`: the particles' box grown by speed times the step plus the solver's per-substep reach, compounded over the substeps) and queries `ctx<PhysicsBroadphase2D>().static_tree` with it, keeping the live Polygon and Compound slots in `collider_order_less_2d` order. That needs the cache up to date (not `dirty`, no pending marks), which it is after `run_physics_2d`; otherwise (a world that only calls `run_fluid_2d`) every polygon and part comes from the component views, which gives the same fluid (`Fluid2DPolygon.StaticCacheAndComponentViewsGiveTheSameFluid`). Movable ones are always read from the views. Projection: the deepest face plane; inside (at or below 0) the particle moves out along that face to one radius, outside within a radius of the polygon it moves out from the nearest boundary point to one radius; at least a radius from a face plane it is left alone. The sweep clips the segment against the edge planes moved out by the radius (Cyrus-Beck; sharp corners, like the box).
  - `SdfCollider2D`, static or under a Kinematic body (skipped under a Dynamic body, as the solver skips it): batches of 64 particles in field-local space, one `sample_many`; a sample below the radius (kept below `band`) moves the particle out along `gradient` to the radius. Deeper than the band, or in a flat region (unallocated `Solid` space reads `-band` everywhere), the gradient is zero and nothing happens: such a particle stays in the solid.
  - `BoxCollider2D` (oriented by yaw) and `CircleCollider2D`, non-trigger, static, kinematic or dynamic: a particle within a radius of the shape moves out along the axis of least penetration (box) or radially (circle). A body moving through the fluid displaces it, and the push becomes particle velocity through `(p - x) / dt`.
  - Swept first (LQ-59): after each iteration's apply, a particle that moved more than half a radius (`kSweepRadii`) in that iteration is swept along the move, from where the previous iteration left it (the substep start for the first iteration, whose move includes the predicted step `v dt`), against every selected boundary, and stops at the first contact, 0.01 radii (`kSweepSkinRadii`) off the surface along its normal, which becomes its contact normal. Circles: the segment against the circle grown by the radius. Boxes: a slab test against the box grown by the radius in its own frame (square corners), the entry face giving the normal. SDF fields: `sweep_circle` in field-local space (segment AABB first, against `allocated_bounds` unless `Solid` outside). A particle that starts in contact and moves further in stops where it started; one that moves away is left to the projection. A step of at most half a radius starting a radius off a wall cannot pass the middle of a wall half a radius thick, so resting and slow fluid pays one length test per particle. A wall thinner than a cell exists in an `SdfField2D` only where it covers a sample, and a sweep cannot stop at a wall the field does not hold. `select_boundaries` culls shapes by the AABB of the substep starts and predicted positions together, so a shape between them is kept.
  - SDF clearance cache (LQ-55): each particle keeps where its SDF fields were last sampled and its clearance there, the smallest `distance - radius` over the fields (or the distance to a field's allocated box when it is outside). An interpolated field changes at most `sqrt(2)` times as fast as the point moves (its samples are 1-Lipschitz, and CSG and clamping keep that), so while the particle is closer to that point than half its clearance no field can push it and its samples are skipped; the result is unchanged. A push, a contact or `Solid` outside resets it, and every step starts without one, since fields change between ticks.
  - Order inside an iteration: the sweep, then shapes, then SDF fields, so a particle squeezed between a moving shape and the terrain ends outside the terrain and is pushed off the shape on a later iteration.
  - Response: a particle moved by a boundary this substep keeps the last contact normal. After the velocity update its normal speed is at least `-restitution` times its approach speed before the solve, and its tangential speed is scaled by `1 - friction`. The collider's own `friction` and `restitution` do not apply.
  - Two-way coupling (LQ-56): a box, circle or polygon collider on the entity of a Dynamic `RigidBody2D` (not on a child of one: only the body's own collider gives the solver its inertia) is tagged with its body (`CouplingBody2D`, in the order of the bodies' first colliders). Each time such a shape moves a particle by `moved` (a projection, or a sweep that stopped on it), the push is added to one of the particle's two coupling slots for that substep (`kCouplingSlots`; a third body adds to the second slot), with its moment `cross(contact - origin, moved)`, the contact one radius behind the particle along the normal and `origin` the body's world position, the solver's center of rotation. After the substep the slots are summed serially in particle order into the bodies, scaled by `-mass / sub_dt`, where a particle's mass is `Fluid2DParams::density` (mass per unit area, default 1, in the units of `RigidBody2D::mass` over a collider's area) times its lattice cell `(2 radius)^2`. So the result does not depend on the worker count. At the end of `run_fluid_2d`, every fluid stepped, each body gets `velocity += impulse / mass` and `angular_velocity += angular_impulse / inertia`, with the solver's mass rule (`kMinDynamicMass`) and inertia rule (the first non-trigger box, circle or polygon on the entity, about its origin; `inertia_2d.h`); the next `run_physics_2d` integrates that. The internal solver deltas are symmetric pair terms that sum to zero, so in a resting pool the pushes on a body balance what the water above and beside it weighs: buoyancy follows Archimedes (a box of density 0.6 floats with 0.6 of its height under water, within a few hundredths of a unit), off-center pushes right a tilted plank, and a body moving through water is slowed by the particles it displaces (pressure drag; the particles' `friction` acts on their velocity only and pushes nothing back). A sleeping body stays asleep unless the change would wake it (`kSleepLinear`, `kSleepAngular`), then its sleep counter is cleared. A body floating at rest never falls asleep: between ticks its stored velocity holds the reaction to this tick's weight (about `g dt` upward), which the next integrate's gravity cancels. `density` 0 turns the reaction off (one way). The reaction is explicit (the body did not move while the fluid was solved), so a body much lighter than the water would overshoot: `apply_coupling` caps the change so the body does not end faster along it than the fastest particle that pushed it this tick plus `|g| dt`, nor spinning faster than that speed over its longest contact arm (unless it already was). A floating body ends each tick near rest and is never capped. From about 0.15 of the water's density up a floating body comes to rest; lighter ones bob at the surface (a box of 0.02 hops up to about its own height times four) but stay in the pool.
  - Order (LQ-64): the shapes and the SDF fields are sorted by content before a step (`shape_content_less`: kind, box, frame, size, vertices, layer, mask by their bits; `sdf_content_less`: frame, origin, cell size, band, layer, mask, then `SdfField2D::hash`), so two peers holding the same colliders read them in the same order whatever their entity order, and a lone peer's result does not depend on creation order either. `FluidStepOptions2D` (`push_bodies`, `movable_from_world`, `movable`) lets a peer step against movable colliders it is handed instead of its own: `movable_fluid_boundaries_2d(world)` returns those a world has, as `FluidBoundary2D` (box: position, X axis, half extents; circle: position, radius; polygon: world vertices; layer and mask). Stepping with that list and `movable_from_world = false` gives the same bits as stepping the world's own. Net sync uses it ([Net](Net.md#fluids)).
  - Static boxes and circles are read from the views every tick, not from the solver's cache: a level of thousands of small static boxes should be a `CompoundCollider2D` or an `SdfCollider2D`.
- Several fluids (LQ-62): `fluid_groups` joins two fluids when their particles' boxes, grown by each one's kernel support, overlap and each one's `mask` takes the other's `layer`, transitively by union-find over view indices (the lower index's group wins), at most 32 to a group (a member bit each; a 33rd starts its own group). `Fluid2DSolver::step` solves a group as one system: the members' particles are gathered in member order into the scratch arrays, with per-particle `owner`, radius, relative mass and `1 / rest density`, and scattered back after. Shared: the largest `h` (pair terms must be symmetric; each member's rest density is then its own lattice's at that `h`), the most `substeps` and `iterations`. Each particle keeps its fluid's gravity scale, relaxation, tensile term, delta clamp, friction, restitution, viscosity, vorticity and coupling mass; cohesion acts only between particles of the same fluid. Boundaries are selected for the group with a member bit per collider and SDF field (each member's own layer rule), and a particle meets only the colliders of its bit. Mixing: a particle's relative mass is its fluid's `density` times `(2 radius)^2` over the group's heaviest (at least a thousandth); the density constraint stays a number density, and every correction is scaled by the particle's inverse relative mass (the denominator sums each neighbour's gradient over its mass, the delta of particle i is multiplied by `1 / m_i`, and a neighbour's lambda is taken in units of its own rest density). At an interface the lighter particle yields and the heavier one sinks. On top, buoyancy: `a = -g (m_around - m_i) / m_i`, `m_around` the poly6-weighted mean mass of the particle and its neighbours, clamped to two `g`, zero inside one fluid. A group of one has every ratio exactly 1 and skips the buoyancy pass: a lone fluid's step is bit-identical to the single-fluid solver (the golden hashes did not change). Tested (`Fluid2DMultiple`): oil of density 0.4 dropped as a blob into a pool of water ends entirely above the pool's 90th-percentile height and comes to rest, a blob of 2.5 sinks to the bottom, two fluids apart step as alone, masks that exclude each other pass through, and results match for any worker count. A light layer started under a heavy one turns over but stops short of two clean layers: a resting PBF fluid jams like a granular pile. Contacts: after the step, every neighbour pair of the last substep whose particles belong to two members is counted once (lower index first), serially in particle order; each member pair that touches sends a `FluidContactEvent2D` (`a`, `b` in view order, `count`, the mean `center`, the box `min` and `max` of the pair midpoints).
- State (LQ-61): by default particles are transient: `fluid_2d` is serialized with parameters, sources, drains and sensors, and a loaded fluid is empty. With `save_particles` the writer adds `state`, the base64 of `Fluid2D::save_state()`, and the reader feeds it to `load_state`, so the loaded fluid has the same `state_hash` and steps on identically (`Fluid2DSave`). The state is little-endian, floats by their bits: magic `WLF1`, version 2, the particle count and per particle position, velocity, density, rest ticks (u16) and asleep (u8), then each source's `carry` and `emitted`, each drain's `drained`, each sensor's `fill` and `full`, then the sleep marks (valid, the key of gravity and parameters, and per mark its key and box). Version 1 (no sleep state) still loads, every particle awake. `load_state` refuses (and changes nothing for) a wrong magic or version, a truncated or overlong buffer, a non-finite value, or more particles than `max_particles`; the source, drain and sensor parts apply only where their counts match the fluid's lists. The same bytes are what a server sends a client that joins late. Not registered for network replication ([Net](Net.md)).
- Authoring (LQ-61): `FluidBox2D` (`size`, `velocity`, `filled`; serialized as `fluid_box_2d`) on a child of the fluid's entity is a pool placed in the scene: the first `run_fluid_2d` after it appears fills `Fluid2D::spawn_box` of the box (world position of the box entity, axis-aligned, `size` full extents) into the parent's fluid and sets `filled`, which is saved, so a world saved after the fill does not fill again. A box whose parent has no `Fluid2D` waits. The editor's World tab draws it and the lattice it will fill ([Editor](../features/Editor.md#world-panel-and-editor-camera)).
- Cost (RelWithDebInfo, defaults): per substep a neighbour search (about 80 hash candidates per particle), per iteration two passes over about 24 neighbours and one SDF sample per particle near a field. A 4k-particle dam break in an SDF tank is about 10.5 ms a tick serial and 1.9 ms on the default threads (6 cores, 12 threads); 16k is about 50 ms serial and 8.2 ms threaded. With `sleep` on, the same 4k pool once asleep costs what is left: about 0.12 ms serial or threaded, against about 10.8 and 2.1 awake (the compound tank 0.2). See [Physics Bench](../features/Physics%20Bench.md#fluids-lq-27).

### 3D physics

`run_physics_3d` is registered once, in `register_simulation_systems`, on `Schedule::Fixed` / `Phase::Physics`, immediately after `run_physics_2d`. Games must not register it again. `dt` is `Time::fixed_delta_time`. `Physics3DConfig` is a world resource, default gravity zero, not serialized. The default `BodyType` is kinematic.

The pipeline matches 2D, with a world quaternion instead of a Z yaw:

1. Kinematic bodies only: `local.position += velocity * dt`. No angular integration for kinematic or static.
2. `update_world_transforms`.
3. Dynamic bodies, snapshotted, parents first. `velocity += gravity * gravity_scale * dt`, then `set_world_position(world_position + velocity * dt)`. Then, still parents first, `rotation = quat(ω dt) * rotation` for a root, and `normalize(inverse(R_parent) * quat(ω dt) * R_parent * R_local)` for a child. `quat(ω dt)` is `angleAxis(|ω| dt, ω/|ω|)`. An `angular_velocity` of exactly 0 is skipped so identity stays identity.
4. `update_world_transforms`.
5. Gather `BoxCollider3D`, then `SphereCollider3D`, then `CapsuleCollider3D` at the world position and the quaternion chain. Scale is not applied. Publish `CollisionEvent3D` from this pre-solve pose. Overlap memory is `ctx<PhysicsOverlapState3D>`. Exit zeros the normal, the penetration, and the point. A pair of colliders on the same entity is skipped, and a second shape pair of the same two entities keeps the first manifold.
6. Non-trigger pairs with at least one dynamic body, sorted canonically by `(min(Entity), max(Entity), shape, item)`. Real overlaps are partitioned into connected dynamic islands (`build_contact_islands` in `src/ecs/contact_islands.cpp`, where static and kinematic bodies do not bridge separate dynamic islands), ordered by lowest entity id. The 3D solver uses a hybrid two-level parallel strategy: independent small and medium islands (`<= 100` dynamic bodies) execute in parallel across `JobSystem::parallel_for` (one island per task), whereas large islands (`> 100` dynamic bodies) build a `ContactColorGraph` (`src/ecs/contact_graph_coloring.cpp`) and solve each color in parallel across worker threads per iteration. `solve_position_iteration_3d` (`src/ecs/solver_3d.cpp`) takes no `World`. The system writes dynamic `velocity`, `angular_velocity`, and `set_world_position`. Kinematic and static angular velocities are copied in for the point velocity and are not written back. The shape rotation is sampled at gather and held fixed for the iterations. The solver does not rotate the body while iterating.
7. `ctx<PhysicsContactCache3D>` seeds one normal impulse and two tangent impulses when `dot(cached_normal, new_normal) > 0`. The seed is not applied to velocity. The cache is replaced by pairs that overlapped and is not serialized.
8. `update_world_transforms` once more.

Positional correction is the mass-only push of the one contact point: `depth = max(0, penetration - kContactSlop)`, A moves `-n * depth * inv_a / inv`, B moves `+n * depth * inv_b / inv`. Two tangent axes: `t1 = normalize(n × +Y)` when `|n.y| < 0.9`, otherwise `normalize(n × +X)`, and `t2 = n × t1`. Each tangent is clamped on its own to `±μ j_n` (a pyramid). Friction is `sqrt(fa * fb)`, restitution is `max(ra, rb)`, and restitution is 0 when `v_rel_n >= -kBounceThreshold`. `v_point = v + ω × r`. `inv_d = inv_m_a + inv_m_b + dot(ra × d, invI_a (ra × d)) + dot(rb × d, invI_b (rb × d))`. `j_n = -(1+e) v_rel_n / inv_n` when approaching. `ω += invI (r × j)` for a dynamic body only.

`make_contact_3d` (`src/ecs/contact_3d.cpp`, `contact_3d_box.cpp`, `contact_3d_capsule_box.cpp`) does not call `make_contact_2d`. Sphere-sphere, sphere-capsule, and capsule-capsule use the closest points of the segments (a capsule segment is `center ± world_Y * height/2`; parallel overlap uses the overlap midpoint; coincident centers use `+X`). Sphere-box is the closest point on the OBB, and an identity box matches the AABB. Identity box-box is the overlap-box center (X, then Y, then Z). Any other box-box is SAT with one witness. Capsule-box is the closest point of the segment to the OBB, or the deepest interior point when the segment hits the box. A negative radius, height, or size returns an empty manifold. A penetration of 0 is a touch. v1 stores one point.

Inverse inertia is a world tensor `R diag(1/I) R^T`, zero on any axis whose `I` is not positive. Local box inertia is `m/12 * (sy²+sz², sz²+sx², sx²+sy²)` with the full size. A solid sphere is `0.4 m r²` on every axis. A capsule is a uniform-density cylinder of length `height` plus two hemispheres: `V_cyl = π r² h`, `V_sph = 4/3 π r³`, masses split by those volumes, `I_axis = 1/2 m_cyl r² + 2/5 m_sph r²`, and the other two axes are the cylinder's `m_cyl (3 r² + h²) / 12` plus each hemisphere's `2/5 m_h r²` shifted by `h/2`. `height == 0` matches the sphere. The first non-trigger collider in gather order supplies `I`. Later solid colliders still contact and do not add mass. A root kinematic's velocity is already world space. A kinematic child contributes `world_matrix(parent) * vec4(velocity, 0)`, scale included; its own rotation is not applied to that velocity. Collider size still ignores scale. Sleep and the broadphase match the 2D pipeline. `kSleepLinear` and `kSleepAngular` are `0.05` (angular speed is `length(angular_velocity)`) and `kSleepSteps` is 8. The quiet counter is `ctx<PhysicsSleepState3D>`. `RigidBody3D.sleeping` is serialized and a missing key loads false. Do not give a predicted or controlled entity a `RigidBody3D`. `run_physics_3d` runs outside prediction `step`, so a kinematic body still integrates and a dynamic body is solved. Characters and tiles stay on `sweep_aabb`.

### Grid queries

`include/engine/ecs/grid_query.h`, `src/ecs/grid_query.cpp`. Collision against a grid of solid cells and a ray through cells, for block worlds and tile games. Pure math like [Ray queries](#ray-queries): no world, no components, nothing registered. It needs no rigid-body 3D physics.

Grid space: cell `(i, j, k)` covers `[i, i+1) x [j, j+1) x [k, k+1)`. The cell size is 1 and the origin is 0; there is no cell-size parameter, so the caller scales world coordinates into grid space (a ray's `t` survives the scaling when its direction is scaled too). +Y is up. Precision: keep coordinates within about +-8192 cells, where a float step is still finer than `kGridSkin`; a position snapped to a face is an exact integer at any range.

`is_solid` is a `CellPredicate<glm::ivec3>` (2D: `glm::ivec2`): a non-owning reference to a `bool(Cell)` callable, two pointers and one indirect call per cell, like C++26 `std::function_ref`. It is valid only for the call it is passed to; never store one. Pass a lambda at the call site; a free function goes through a lambda or a function-pointer variable. The algorithms stay in the `.cpp` (one template over the dimension), so a game does not compile them.

| Function | Result |
| --- | --- |
| `raycast_grid(ray, max_distance, is_solid)` | `std::optional<GridHit>`: the first solid `cell`, the face entered (`normal`, one axis +-1, facing back along the ray; `cell + normal` is the cell the ray came from), `t` and `point` |
| `raycast_grid(origin, direction, max_distance, is_solid)` | 2D over `glm::vec2`: `GridHit2D` |
| `sweep_aabb(box, delta, is_solid)` | `GridSweep`: the resolved `render::Aabb`, `moved` (the applied displacement), `hit` per axis (0 free, +1 blocked moving +axis, -1 blocked moving -axis), `grounded()` = `hit.y < 0` |
| `sweep_aabb(min, max, delta, is_solid)` | 2D: `GridSweep2D` |

Ray (Amanatides-Woo DDA):

- `t` and `max_distance` are multiples of `direction`, as in `ray.h`: distances for a unit direction. `t <= max_distance` hits.
- A boundary is half-open in the direction of travel: a ray that starts on a face and points away does not touch the cell behind it.
- A ray that starts inside a solid cell reports `t = 0`, a zero normal and the origin, even with a zero direction or `max_distance = 0`.
- A ray exactly through an edge or a corner (boundary `t` equal within 1e-6, relative) is blocked by any solid cell that touches it there. The side cells are tested x, y, z, then xy, xz, yz, then the diagonal cell; the normal is the first stepped axis of that cell. A line of sight cannot slip through the seam between two diagonal blocks.
- nullopt: a miss within `max_distance`, a zero direction outside a solid cell, `max_distance < 0`, or a non-finite input (or a coordinate of 2^24 or more, where a float no longer tells one cell from the next).

Sweep:

- Axis-separated: Y, then X, then Z (2D: Y, X). Each axis stops flush against the first solid face ahead of the box. Every face crossed along the axis is tested, so no speed tunnels through a wall.
- A move is cut into `ceil(max |delta|)` sub-steps, so a fast diagonal move cuts no corner larger than a cell. A box or delta of 2^24 or more returns the box unmoved. An axis blocked in one sub-step stays blocked; the others keep sliding.
- `kGridSkin` (1e-3 grid units): the cells across the motion come from the box shrunk by the skin, so a box resting on a floor or flush against a wall slides along it and does not catch on cell seams. A box sunk up to the skin into a face it moves toward snaps back onto it. A box resting on a floor under a downward delta snaps to exactly the same face every call: grounded, no drift, no jitter.
- A move that ends exactly on a face counts as blocked. A zero delta on an axis reports no hit there.
- Cells the box already overlaps deeper than the skin are ignored: a box inside a solid is never stuck, and is not pushed out.
- No step-up: a one-cell step blocks horizontal motion. A reversed bound is swapped. A non-finite box or delta returns the box unmoved.

The engine has no tile collision flag; a tile layer is a lambda. Tilemap rows run down while y runs up, so grid cell `(x, y)` is row `-y - 1`: `map.tile(layer, c.x, -c.y - 1) != 0`, with the box taken relative to the map's position and divided by `TilemapAsset::cell_size()`.

### SDF fields

`include/engine/ecs/sdf_2d.h`, `src/ecs/sdf_2d.cpp`. `SdfField2D` is a chunked 2D signed distance field for destructible terrain (dig, blast, build) and the data that later SDF collision reads. Pure math like [Grid queries](#grid-queries): no world, no components, nothing registered; the 2D solver collides with one held in an `SdfCollider2D` ([SDF colliders](#sdf-colliders)), which is how it is serialized. It owns its storage; copy it like a value.

Conventions:

- Negative inside solid, positive in empty space, zero on the surface. `gradient` points out of the solid.
- Samples sit at cell corners: sample `(i, j)` is at `origin + cell_size * (i, j)`, and cell `(i, j)` is the bilinear patch between samples `(i, j)` and `(i + 1, j + 1)`. +Y is up, as in the grid queries.
- Chunks of `kSdfChunkCells` (32) x 32. Chunk `(cx, cy)` owns samples and cells `[32 cx, 32 cx + 32) x [32 cy, 32 cy + 32)` (`chunk_of` is a floor division; coordinates may be negative). Each sample belongs to exactly one chunk, so a seam holds no duplicated value that could disagree; the cells on a chunk's right and top rows read the neighbours' samples. Chunk boundaries line up with tilemap chunks: with `origin` at the map's top-left corner and `cell_size` its (square) cell size, field chunk `(cx, cy)` covers tilemap chunk `(cx, -cy - 1)` (tilemap rows run down).
- Sparse: a chunk is allocated only when an edit changes it (or dirties it, below). Everywhere else reads the field-wide `outside`: `SdfOutside::Empty` (+band, build in empty space) or `SdfOutside::Solid` (-band, dig into a solid world).
- Storage is one `int16` per sample (2 KB a chunk), the distance quantized over `[-band, +band]` (`band / 32767` per step) and clamped there. Beyond the band a distance is only known to be at least `band`.
- `SdfField2DDesc`: `cell_size` (non-finite or not positive: 1), `band` (non-finite or not positive: 4 cells; below one cell: one cell), `origin`, `outside`.

Queries are `const`, deterministic, and do not allocate. A non-finite position, or one 2^24 cells out, reads `outside`.

| Function | Result |
| --- | --- |
| `sample_at(index)` | The stored distance at a sample |
| `sample(p)` | Bilinear distance |
| `gradient(p)` | Unit normal: the analytic gradient of the bilinear cell; central differences half a cell to each side when that is degenerate (a saddle, a flat cell); zero when both are flat |
| `raymarch(origin, direction, max_distance)` | `std::optional<SdfHit2D>`: `point`, `normal`, `distance` along the normalized direction |
| `sweep_circle(center, radius, delta)` | `std::optional<SdfSweep2D>`: `fraction` of `delta` in [0, 1], `center` there, contact `point`, `normal`, `depth` |

- `raymarch` is sphere tracing: each step is the sampled distance, at least 1/10 of a cell (a feature thinner than that can be stepped over). The first sign change (`d <= 0`) is bisected to 1e-4 of a cell and the hit is on the empty side of it. A ray that only grazes the surface misses. A ray that starts at or inside the surface hits at distance 0. With `Empty` the ray is first clipped to the rectangle of allocated chunks, so a long ray past the terrain is free. nullopt: a miss, a zero or non-finite direction, a negative or non-finite `max_distance`.
- `sweep_circle` is conservative advancement on `sample - radius` with the same stepping and refinement, so the returned center does not penetrate. A circle that starts touching or penetrating reports fraction 0, `depth = radius - d`, `point = center - normal * d`. `radius` must be below `band`, since the field cannot tell surfaces apart beyond it; a larger radius returns nullopt. Choose the band larger than the largest swept circle.

Edits return the chunks they dirtied, sorted by y then x, unique, and bump each one's revision once. A chunk is dirty when any cell it owns changed, that is, when one of a cell's four corner samples changed value; a changed sample in a chunk's first column or row also dirties the chunk to its left or below (allocating it, filled with `outside`, if needed). An edit that changes no sample (carving empty space, repeating the same edit) returns nothing and bumps nothing. `revision(chunk)` is 0 for an unallocated chunk and starts at 1; `chunk_coords()` lists allocated chunks; `chunk_samples(chunk)` is the raw `int16` row-major array from the bottom row.

- `fill_circle`, `carve_circle`, `fill_polygon`, `carve_polygon`: CSG with the exact shape SDF in the quantized domain, fill `min(d, shape)`, carve `max(d, -shape)`, over the samples within the shape's bounds grown by `band` only (outside them the shape cannot change a clamped value). A polygon is convex and CCW in world space with no vertex cap; fewer than 3 vertices, a non-finite vertex, a zero-length edge, a clockwise turn, or a non-positive area is a no-op (the `PolygonCollider2D` rules), and a collinear turn is kept. A non-positive radius is a no-op.
- `fill_from_mask(min_cell, size, is_solid, cells_per_mask_cell = 1)`: a solid-cell mask (a tile layer, a bitmap) to exact distances. Mask cell `(x, y)` is the square of `cells_per_mask_cell` field cells per side; `is_solid` is the same `CellPredicate<glm::ivec2>` as the grid queries, so a tile layer is `map.tile(layer, c.x, -c.y - 1) != 0`. A sample gets the distance to the union of solid squares (integer math, then one `sqrt`), 0 on its boundary. Mask cells outside the rectangle read as `outside`. Samples inside the rectangle are overwritten; in the band-wide margin around it they are merged (`min` with `Empty`, `max` with `Solid`), so a mask joins terrain already there. A shape one field cell thick has no negative sample; use 2 or more field cells per mask cell for one-tile platforms. Cost: one predicate call per mask cell, and per written sample a scan of the mask cells within the band.
- `renormalize(chunk)` / `renormalize(span)`: repeated CSG leaves a distance bound (two overlapping carves read the nearer circle at the lens center, not the cusps). The chunk's samples are recomputed as the exact distance to the piecewise-linear zero crossing, keeping each sign: marching squares over the chunk plus a halo of `h = ceil(band / cell_size) + 1` samples from its neighbours, crossings by linear interpolation along cell edges, a saddle split by the cell's mean, then, per sample, a brute-force scan of the segments of the `(2h)^2` cells around it. That is about `1024 * (2h)^2` cell visits a chunk (about 100k for a 4-cell band). A sample's result depends only on samples within `h` of it, computed relative to the sample, so a seam gives the same bits as the middle of a chunk. The span form computes every listed chunk from the field as it was before any changed, so the order of the list does not matter; pass an edit's dirty list. It is a near fixed point, not an exact one: a second pass moves curved interfaces by rounding only.

- `assign_chunk(chunk, samples)` overwrites one chunk with raw samples (the `chunk_samples` layout), for loading; it follows the edit rules, and a newly allocated chunk is always dirty. `edit_count()` is bumped once by every edit that dirtied a chunk (0 for a field never edited), so a cache of the field can tell that something changed without comparing chunks. `sample_many(points, out)` is `sample` per point, bit-identical, with one chunk lookup per run of points in the same chunk.

`allocated_bounds()` is the field-local rectangle of allocated chunks grown by one cell (the cells next to it still read its samples), nullopt with no chunk: beyond it every query reads `outside`. `raymarch` clips to it with `Empty`, and particles reject against it. Particles collide with a field through `SdfCollider2D` ([Render](Render.md#sprites-animation-particles-curves)). Not here yet: LQ-27 uses the field as a fluid boundary.

## World serialization

`include/engine/ecs/world_io.h`, `include/engine/ecs/world_asset.h`, `include/engine/ecs/world_serializer.h`.

`.world` TOML files (`importer = "world"`) parse into a `WorldAsset` (`version = 1`, optional `active_camera`, and `[[entities]]` with `id`, optional `parent`, and `[entities.<component>]` tables).

- `WorldSerializer` (available via `world.ctx<WorldSerializer>()`) comes pre-populated with built-in engine components: `transform`, `camera`, `sprite`, `sprite_animator`, `renderable`, `tilemap`, `directional_light`, `ambient_light`, `point_light`, `spot_light`, `fog`, `rigid_body_2d`, `box_collider_2d`, `polygon_collider_2d`, `compound_collider_2d`, `sdf_collider_2d`, `circle_collider_2d`, `fluid_2d`, and `pointer_target`. `rigid_body_2d` writes `angular_velocity`; a missing key stays 0. `polygon_collider_2d.vertices` is an array of `[x, y]` of length `count` (more than 8 fails the load). `compound_collider_2d.shapes` is an array of tables `{ vertices = [[x, y], ...] }` with the same 8-vertex limit, plus `layer`, `mask`, `friction`, `restitution`; a prototype variant that overrides `shapes` replaces the whole array. `sdf_collider_2d` writes the field description `cell_size`, `band`, `origin` (`[x, y]`), `outside` (`"empty"` or `"solid"`), then `chunks`, an array of tables `{ x, y, samples }` with one per allocated chunk where `samples` is base64 (`src/core/base64.h`) of the 1,024 quantized samples as little-endian `int16`, plus `layer`, `mask`, `friction`, `restitution`. Any of the field keys rebuilds the whole field (a missing description key keeps the current value, chunks go through `assign_chunk`); a variant that sets only `layer` keeps the field. A sample string that does not decode to 2,048 bytes, a chunk without `x`, `y` or `samples`, or another `outside` fails the load. Each entry's `remove` drops that component; `register_component` installs it. Removing `sprite`, `sprite_animator`, `renderable`, or `tilemap` also clears the asset ids saved for that component.
- Game-specific components marked `struct WIND_COMPONENT MyComponent { ... };` are registered by calling `assets::register_game_components(world.ctx<WorldSerializer>())` from the generated `<component_io.h>` header (see [Asset Codegen](../build/Asset%20Codegen.md#component-codegen)), or by calling `GameModule::register_components(serializer)` (`wind_register_game_components`).
- `struct WIND_SERIALIZABLE Value { ... };` is not a component. The same header emits `encode_wind` / `decode_wind`, so a component field of that type (or a `std::vector` of it) is nested in the component's table in the `.world` file and is not its own asset. `AssetId` on a component stays a guid; the game loads the referenced `.object` with `AssetsDb::get<T>`. `assets::register_game_objects` registers those loaders (`GameModule::register_objects`, `wind_register_game_objects`).
- `instantiate_world(world, asset, &assets, serializer, unknown_mode)` and `load_world_from_toml` spawn entities in two passes (entities and `EntityName` first so `ecs::Entity` cross-references resolve in any order, then hierarchy and components), set `ActiveCamera` when `active_camera` is non-empty, and call `update_world_transforms(world)`. On any error, newly created entities are rolled back.
- `UnknownComponentMode::Reject` (default) fails with `WorldErrorKind::UnknownComponent` when a component key is not registered in the active `WorldSerializer`. `UnknownComponentMode::Preserve` stores unregistered component tables in `UnknownComponents` (`std::map<std::string, FieldTable, std::less<>> components`) on the entity so the editor can inspect and round-trip game components without losing data when the game module is not loaded.
- `capture_world_asset` and `save_world_to_toml` snapshot all alive entities (`World::alive_entities()`), their registered components, and any preserved `UnknownComponents` entries back to a `WorldAsset` or TOML string.

## Prototypes

`include/engine/ecs/prototype_asset.h`, `src/ecs/prototype_asset.cpp`.

`.prototype` TOML files (`importer = "prototype"`) define reusable entity templates and hierarchies, optionally inheriting from a `base` prototype GUID (Prototype Variants):

- `PrototypeAsset` contains `version = 1`, optional `base` (`AssetId`), and `[[entities]]` records.
- `resolve_prototype_asset(asset, &assets)` resolves the variant inheritance chain, detecting cyclic references (`PrototypeCycle`), deep-merging component `FieldTable`s (via `merge_field_tables`), preserving base children, and adding new entities or components.
- In `.world` files, entities reference prototypes via `prototype = "<AssetId>"`. During `instantiate_world`, prototype hierarchies are automatically expanded, world-level entity overrides (including child entity overrides via `id = "<entity_id>/<child_id>"`) are deep-merged, and `PrototypeInstance{ prototype, entity_sub_id }` is attached to every spawned entity.
- Programmatic spawning in C++: `spawn_prototype(world, prototype_id, assets, params)` spawns a prototype into an active world with optional position, rotation, scale, and parent entity.

## Models

`include/engine/ecs/model.h`, `src/ecs/model.cpp`. The cooked asset is [Assets](../features/Assets.md#models); the draw is [Render](../modules/Render.md#skinning).

A `.world` entity with a `model` component (`ModelPlacement`: asset id and clip name) is expanded by `instantiate_world` after its other components are read, the same way a prototype is. `spawn_model(world, id, assets, params)` does the same for a new root: position, rotation, scale, and parent, matching `spawn_prototype`.

The root gets `Transform` and `ModelAnimator`. Each primitive is a child (`Parent`) tagged `ModelPartTag`. The first primitive of a node drives that node's transform; further primitives of the node parent to it. `capture_world_asset` skips `ModelPartTag`, so saving the world does not write the generated hierarchy back. Model meshes are not catalog entries.

`run_model_animations` is `Schedule::Frame`, `Phase::Game`, and advances by `Time::delta_time` (presentation, like sprite frames). It writes each driving part's local `Transform` from the glTF global of its node, decomposed to TRS, before `update_world_transforms`. `play(clip, fade_seconds)` is layer 0. `play_layer(index, clip, fade_seconds)` starts that layer, creating slots up to `index`. Each layer has its own clock, loop, speed, weight, and crossfade. A fade of 0 switches immediately; otherwise the previous pose of that layer blends out with a linear blend and a slerp of rotation. `ModelBlend::Override` mixes the layer onto the pose under it. `ModelBlend::Additive` adds the clip's delta from the rest pose. `mask` empty is the whole body; a name is that node and its descendants. A name that matches no node leaves the pose unchanged and sends no markers; the clock still advances. A later layer wins where masks overlap. Weight 0 still advances the clock and sends no markers. Markers authored on the model's `.meta` ([Assets](../features/Assets.md#models)) ride every layer whose weight is above 0 and whose mask names a real node. A tick sends one `ModelAnimEvent` (`entity`, `clip`, `name`) for each marker in `(previous, next]`, and the tick after `play` or `play_layer` also sends markers at time 0. The clip `spawn_model` and world expansion start does the same on its first tick. A loop fires each crossing, including the wrap through 0. A paused layer or a `speed` of 0 sends nothing. The clip being faded out sends nothing, so cancelling an attack does not fire the swing it left. The event is not damage: a game system on this same frame latches a component, and the fixed step reads that component. `flush_events` runs at the start of the next tick, before `Schedule::Fixed`, so a fixed system that reads `ModelAnimEvent` directly can miss it on a frame that takes no fixed step. After the layers, each `ModelJointSpring` integrates on the same frame delta and adds its offset to that node's local pose; children follow through the hierarchy. `impulse_joint(animator, name, world_direction, strength, root_world)` adds velocity on that node (a second call in the same tick sums). The direction is world space, mapped by `root_world` (identity when the root is unrotated). The spring settles back to the clip pose. `joint_world(world, root, name)` is that node's global matrix times the root's world matrix, without the inverse bind, for attaching something to a bone. `nearest_joint(world, root, point)` is the node whose posed world position is closest to `point`. The engine does not collide the shot. There is no entity per bone.
